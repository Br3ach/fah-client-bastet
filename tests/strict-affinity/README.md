Client-owned strict FahCore launch tests. Windows: from a Visual Studio x64 terminal, run python tests/strict-affinity/run.py --cbang PATH_TO_UPSTREAM_CBANG. The runner compiles the actual CoreProcess.cpp plus win/CoreProcessLaunch.cpp and links unchanged cbang. It verifies singleton and expanded process masks, including inheritance by new Windows threads, in the child and proves invalid masks never execute the payload. Linux checks include singleton and multi-LP pools and launches with closed standard file descriptors. Linux: python3 tests/strict-affinity/linux-native.py executes the shared dispatcher and complete Linux launch body, including its descriptor owners with real OS syscalls and lifecycle adapters.

Graceful interruption is tested with a child that installs its handler before signalling readiness. The parent invokes the production stop/interrupt path and requires interrupt receipt, exit code 42 and no forced kill within five seconds. Windows tests the linked CoreProcess with CTRL_BREAK and a dedicated process group. Linux extracts the production stop/interrupt bodies and exercises SIGINT with real process-group syscalls. Windows creates a console for the isolated test family if the runner has none.

Windows failure injection also checks a child that has already exited when termination reports failure, and a live suspended child whose termination fails. The latter stays owned by the launcher, blocks additional strict launches, and is reaped when cleanup retries succeed. Rejections remain on affinity cooldown rather than consuming work-unit retries.
